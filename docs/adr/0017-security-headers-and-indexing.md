# ADR 0017: One security policy for pages and API, and what search engines may see

Status: accepted

**Context.** The Worker serves two kinds of response. Static files (the app, fonts, images) come from Workers static assets, which can add headers only through a `_headers` file. Everything under `/api/*` is generated by the Worker's own code, where `_headers` has no effect. Until now neither carried any security header, and `/robots.txt` and `/sitemap.xml` returned the app's HTML. The voter page and the invite code it carries are the sensitive part: a page that can be framed, can load a third-party script or leaks its address in a `Referer` header would undo ADR 0015.

**Decision.**
1. **Pages** get `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self'; font-src 'self'; connect-src 'self'; object-src 'none'; frame-ancestors 'none'; form-action 'self'; base-uri 'none'`, plus HSTS, `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` (everywhere, not only `/vote/*`: no page links to a third party that needs the referrer), `Permissions-Policy` allowing `publickey-credentials-get` and `-create` for this origin only, `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Resource-Policy: same-origin`. They are written to `dist/_headers` at build time by `apps/web/site.ts`.
2. **API responses** get the same set from `securityHeaders()` in `apps/api/src/security.ts`, with `default-src 'none'` (JSON is never rendered), `X-Robots-Tag: noindex` and `Cache-Control: no-store` unless a handler chose its own (only the published bulletin does: `public, max-age=60`).
3. **No inline script or style.** The page has none, so no nonce or `unsafe-inline` is needed. The one inline-looking thing, the width of a result bar, is set through the DOM by React, which the policy permits.
4. **Telemetry hosts are opt-in at build time.** `connect-src` is `'self'` unless `VITE_SENTRY_DSN` or `VITE_POSTHOG_KEY` is set, in which case `site.ts` adds exactly those ingest origins (and PostHog's project-config host, `<region>-assets.i.posthog.com`). PostHog is told not to load code from its CDN. The SDKs are a separate chunk requested only on public pages and only when a key exists, so a voter's phone downloads none of it.
5. **Cross-site writes are refused twice.** The session cookie is `SameSite=Lax`, `Secure`, `HttpOnly` (Better Auth's defaults, checked in a test). In addition every organiser write, and every POST to `/api/auth/*`, is refused with 403 if `Sec-Fetch-Site` is not `same-origin` or `Origin` is not this deployment's origin. A request with neither header is not from a browser and carries no ambient cookie.
6. **Indexing.** `/` and `/privacy` are indexable, have their own title, description and canonical link, and are the only entries in `sitemap.xml`. `/vote/*`, `/organiser*`, `/verify*` and `/results/*` carry `X-Robots-Tag: noindex, nofollow, noarchive` as a header, and the app also sets `<meta name="robots" content="noindex…">` and removes the canonical link when it shows one of them. `robots.txt` disallows only `/api/`: a crawler that may not fetch a private page can never read its `noindex`, and could still list the bare URL.

**Consequences.**
- Adding any third-party script, font host, image host or analytics endpoint now needs a change to `site.ts` and a reason. That is the point.
- Cloudflare joins the values of a header named in several matching `_headers` rules, so `site.ts` never repeats one; `site.test.ts` and `e2e/security.spec.ts` check this against the real files.
- The unknown-path response is still the app with status 200 (Workers' single-page-application fallback), so a mistyped address is a soft 404 to a crawler. It is noindex in the page.
- HSTS has no `preload`: `workers.dev` cannot be preloaded by this project. If the app moves to its own domain, add `preload` and submit it.
- `e2e/security.spec.ts` fails on any CSP violation, console error or page error across organiser, passkey registration and authentication, results, receipt check and privacy pages.
